## Реализация и ограничения

Исключения приложений и экран внешнего IP/проверки маршрута не добавлялись по
указанию пользователя. Политика direct для РФ и локальной сети сохранена.
Клиент не создаёт новые серверы: для резервирования нужны собственные
совместимые профили, в том числе разных протоколов при необходимости.

Повторы работают в течение сессии, начатой вручную. Они используют текущий
статус ядра, доступность физической сети и VPN-разрешения Android. После шести
попыток нужно ручное подключение. Бюджет восстанавливается после двух минут
устойчивого Connected. Автоповторы не открывают диалоги разрешений и не выводят
текст исключений. Отзыв разрешения и остановка из уведомления/плитки отменяют сессию.
Таймер Flutter работает, пока жив его процесс. Смена интерфейса сети и выход
из сна обрабатываются существующими Android-службой и native-ядром.

Строгую защиту реализует Android, а не переключатель приложения. Нужно вручную
включить «Постоянный VPN» и «Блокировать соединения без VPN» для Mit’s VPN.
Отключение туннеля при включённой системной блокировке может оставить устройство
без интернета до подключения или выключения блокировки. Доступность настроек
и поведение производителей различаются. На API 29+ статус читается из живой
VpnService; без службы или на неподдерживаемом Android статус не утверждается.
Системный старт службы теперь восстанавливает последнее подключение ядра
без ожидания Flutter RPC; ручной старт через UI сохраняет двухэтапный запуск.

Отчёт собирается по списку разрешённых полей. Не читает профиль, конфигурацию,
сетевые адреса, буфер или сырые логи и не отправляется автоматически. Только
по нажатию после просмотра копируется в системный буфер. Это не аудит всех
существующих upstream-логов и телеметрии приложения.

Ожидается CI. На реальном устройстве остаётся проверить смену Wi-Fi/мобильной
сети, фон и сон, потерю сервера, исчерпание повторов, выбранный резерв,
ручное отключение и отзыв разрешения во время восстановления, системную
блокировку при обрыве/остановке процесса и восстановление после перезапуска.
