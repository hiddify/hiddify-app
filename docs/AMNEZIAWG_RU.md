# AmneziaWG в Mit’s VPN для Android

Приоритет пользователя — клиентские ссылки `vpn://` из Amnezia. В окне «Добавить
профиль» доступны явная вставка из буфера и импорт UTF-8 `.conf`/`.txt`.
Ввод скрыт, автокоррекция и обучение клавиатуры отключены. Добавление не подключает
VPN автоматически; после выбора профиля используется прежняя кнопка подключения.
На домашнем экране и в списке профилей отображается безопасная подпись AmneziaWG.

## Аудит ядра

В приложении закреплено ядро `a1bdfaf39a30e3a8ccafaafcde39fe4d788f6352`;
его Makefile собирает Linux и Android с `with_awg` и `with_wireguard`.
Схема `option/awg.go` из sing-box-подмодуля `fda14fcdb55a08284b210657bdd8b6175e817699`
поддерживает AWG 1.x, 1.5, 2.x и дополнительные параметры 3.x.
Штатный INI-парсер ray2sing `54a3aa1ba927aa53d1f43dba22d27a43cb5c316f`
читает J/S/H/I, но не все параметры 3.x. Поэтому приложение формирует собственный
проверенный `awg` endpoint и передаёт его штатному валидатору ядра.
Сервер Xray, нативный backend и сборки iOS/Windows не меняются.

Формат `vpn://` сверён с официальным
[Amnezia ExportController](https://github.com/amnezia-vpn/amnezia-client/blob/7f9b7db482b8b1662b7466937e578008cbcb716e/client/core/controllers/selfhosted/exportController.cpp):
Base64URL, затем Qt qCompress (длина big-endian и zlib), JSON с одним AWG-контейнером,
`awg.last_config`, затем клиентский INI в поле `config`. Старый вариант без сжатия
также принимается. Исходники изучались отдельно, upstream-подмодули приложения
не обновлялись. Поставляемые сейчас native libraries, как и ранее, загружаются
из draft-релиза upstream; их совместимость проверяется реальным RPC-тестом в CI.

## Форматы и ограничения

* Клиентский `vpn://` с одной AWG-конфигурацией; полный доступ с SSH-учётными
  данными отклоняется. Ключи Amnezia-сервиса (`api_key`/`auth_data`), требующие
  отдельного обращения к провайдеру, пока не поддерживаются.
* Текст `.conf` с одним `[Interface]` и одним `[Peer]`.
* `awg://` с Base64-конфигурацией или параметрами в query.
* Прежняя одиночная ссылка VLESS/TCP/REALITY сохраняет прежнюю проверку.

Проверяются длины ключей, CIDR, IPv4/IPv6, endpoint и порт, MTU, keepalive,
числовые поля и диапазоны AWG. Сохраняются Jc/Jmin/Jmax, S1–S4, H1–H4, I1–I5,
PSK и параметры 3.x, включая HeaderProtectionKey и таймеры. Неизвестные директивы,
скрипты PostUp/PreUp, дубли полей, дополнительные peers/профили, JSON с внешними
маршрутами и подписки отклоняются. Нативный валидатор проверяет endpoint перед
сохранением; скрытого понижения до обычного WireGuard нет.

Пакетные шаблоны I1–I5 проверяются отдельно: разрешены только поддерживаемые
ядром b/t/r/rc/rd/d/ds/dz/qi, валидные аргументы и суммарный размер до 65507 байт.
Отрицательные и чрезмерно большие размеры отклоняются до native parser: upstream
создаёт буфер указанной длины при handshake, поэтому одного ограничения длины
текстового ключа недостаточно.

Вход и распакованный контейнер ограничены 64 КиБ. Реальный объём распаковки
ограничивается отдельно от размера, заявленного в Qt-заголовке. Административные
учётные данные, внешние подписи и исходный контейнер не записываются в профиль.
Ошибки ввода/чтения/ядра не показывают ключи, исходный текст или путь файла.
Буфер читается только по нажатию. Временные копии file picker очищаются после чтения;
исходный файл пользователя остаётся на месте.

AllowedIPs профиля сохраняются. Маршрутизацию РФ/локальной сети и DNS определяет
Mit’s VPN; DNS из INI проверяется, но не заменяет управляемые настройки DNS.
Эта особенность указана в окне импорта. Профили с ограниченными AllowedIPs могут
не обслуживать весь зарубежный трафик; прямой обход из-за этого не добавляется.

## Проверки

Добавлены синтетические ключи/адреса без реального сервера: тесты распаковки,
лимитов, валидации, сохранения параметров разных версий, безопасной обработки
ошибок, вставки и чтения файла, передачи в repository без автоподключения.
Отдельный тест через mTLS RPC вызывает настоящий native core, проверяет тип `awg`,
PSK, AllowedIPs, все заданные параметры маскировки и повторную валидацию сохранённого
JSON. В CI отсутствие native library считается ошибкой этого теста.

Код `e92c0e35953dd37d2a84523c77ac37e8443c777e` проверен [в CI](https://github.com/Mit-ping/Mit-s/actions/runs/41187483637): анализ, тесты пилота,
полный набор, обязательный native AWG RPC-тест, рендеры, сборка и проверка ресурсов APK
прошли. Native library из `hiddify-core/bin/lib/hiddify-core.so` теперь размещается
также по пути `hiddify-core/hiddify-core.so`, который использует Flutter FFI;
отсутствие библиотеки больше не превращает этот AWG-тест в незаметный пропуск.

Дополнительно локальный CLI скачанного draft-ядра v5.2.0 (sing-box
1.15.0-alpha.13, revision `f896546e9acd15c3a8ab093fb213ca314c5db1df`) принял
синтетические endpoint-конфигурации AWG 1/2/3 и сохранил параметры.

[Скачать APK — ZIP, 252 МБ](https://github.com/Mit-ping/Mit-s/actions/runs/41187483637/artifacts/13038006024);
[превью экранов — ZIP, 4,01 МБ](https://github.com/Mit-ping/Mit-s/actions/runs/41187483637/artifacts/13037905750).
Сборка использует временную debug-подпись: перед переустановкой сохраните ссылки
существующих профилей на устройстве.

1. В Amnezia скопировать клиентский ключ «Поделиться подключением» с `vpn://`.
2. В Mit’s VPN: «Добавить профиль» → «Вставить» → «Добавить».
3. Если есть другие профили, в меню «Выбрать профиль» выбрать AmneziaWG.
4. Подключиться обычной кнопкой; зелёное состояние появится только после реального
   подтверждения ядром.

Реальное подключение к AWG-серверу, egress, DNS/IPv6 и смена сети пока не проверены
на устройстве. Реальные ключи остаются у пользователя и не передаются в чат или
тестовые fixtures. Native parse/check подтверждает совместимость конфигурации,
но не доступность конкретного сервера и успешность сетевого handshake.


## Alpha 1.1: совместимость файлов и экспортов AmneziaVPN

После обращения пользователя исправлены фильтр выбора Android .vpn и чтение
текстовых/JSON/Base64URL/Qt binary документов. Поддержаны структурированный
last_config без INI, дополнительные DNS-контейнеры, явный defaultContainer при
нескольких AWG, известные пустые optional fields и переносы в ключе. Неизвестные
директивы, дубли и admin credentials по-прежнему отклоняются.
Непустой INI имеет приоритет; недостающие параметры маскировки берутся из
client/server metadata, пустые клиентские значения не затеняют серверные.
Добавлены безопасные коды AWG-01–AWG-04/FILE-01 без значений профиля.

[Подробный отчёт и текст для Telegram](releases/ALPHA_1_1_RU.md).
[Успешный CI](https://github.com/Mit-ping/Mit-s/actions/runs/41194053959); [APK Alpha 1.1](https://github.com/Mit-ping/Mit-s/actions/runs/41194053959/artifacts/13039809593).
Точный пользовательский экспорт не был предоставлен и не воспроизводился;
проверка на устройстве остаётся открытой.

## Alpha 1.2: HeaderProtectionKey и флаги Amnezia

Импорт принимает HeaderProtectionKey как 64 hex-символа или Base64/Base64URL
ровно 32 байт (с padding или без него). Перед передачей в ядро Base64
преобразуется в hex без потери байт. RandomTrailers и DisableCookies принимают
`on`/`off`, а также прежние `true`/`false` и `1`/`0`, без учёта регистра.
Проверки повреждённых ключей и неизвестных значений флагов сохранены.

Добавлены синтетические регрессионные тесты для .conf, vpn-ссылок, файлов и
метаданных экспорта, а также образец для native RPC-теста. Пользовательский
VPN-ключ в репозитории отсутствует. Версия Android: `1.2.0-alpha` (`50002`).

Код `bebaf9ff15c05cfd2ffda4bf5ecc0fe4d757ece2` успешно проверен
[в CI](https://github.com/Mit-ping/Mit-s/actions/runs/41439433347): анализ,
тесты пилота, полный набор тестов, обязательный native AWG RPC-тест, сборка APK
и проверка упакованного брендинга прошли. Весь запуск занял 13 минут 22 секунды.
Проверки выполнены на GitHub Actions; локальный Flutter SDK не установлен.

[Скачать APK Alpha 1.2 — ZIP, 252 МБ](https://github.com/Mit-ping/Mit-s/actions/runs/41439433347/artifacts/13140935310).
В архиве находятся `one-tap-vpn-debug.apk` и `SHA256SUMS`.
Работоспособность подключения к пользовательскому серверу и handshake на
Android-устройстве пока не подтверждены. Пользовательский файл в этом чате
не прикреплён; проверки файлового импорта используют синтетические данные.
